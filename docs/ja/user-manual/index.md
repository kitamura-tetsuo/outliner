## 基本的な操作

Outlinerの基本的な画面構成と操作方法について説明します。

### ページの作成と閲覧

ページの作成と閲覧は、左側のサイドバーまたは画面上部の検索バーを使用して行います。

ページを閲覧するには、左上のサイドバー切り替えボタン（ハンバーガーメニュー）をクリックし、**Pages**セクションを展開します。ここには、現在のプロジェクト内のすべてのページがリスト表示されます。プロジェクトのホームページにもページが表示されます。グリッドビューとリストビューを切り替えたり、更新日時 (Modified)、作成日時 (Created)、最終訪問日時 (Last visited)、被リンク数 (Most linked)、閲覧回数 (Most viewed)、タイトル (Title) でページを並べ替えることができます。

新しいページを作成するには、サイドバーの**Pages**セクションヘッダーにある**Add new page**（新しいページを追加）ボタンをクリックします。

### 編集モードへの切り替え

テキストをクリックすると、その場所にカーソルが表示され、編集モードになります。

### カーソルの移動

キーボードの矢印キー (`↑` `↓` `←` `→`) を使って、カーソルを自由に移動できます。アイテム間を上下に移動する際、カーソルは水平位置を維持します。

- 行の先頭へ移動: `Home`キー
- 行の末尾へ移動: `End`キー

### ユーザー認証

画面右上のナビゲーションバーにあるユーザープロフィールボタンは、現在のログイン状態（ゲストユーザーの場合は「Not signed in」）を表示します。クリックすることで、アカウントの管理やログインを行うことができます。

### サイドバーナビゲーション

左上のサイドバー切り替えボタン（ハンバーガーメニュー）をクリックすると、メインのサイドバーナビゲーションが開きます。サイドバー内の各セクションは、ヘッダーをクリックすることで展開または折りたたむことができます。サイドバーからは以下の項目に素早くアクセスできます：

- **Projects:** プロジェクトの切り替えやホームに戻ることができます。
- **Pages:** 現在のプロジェクト内のすべてのページを閲覧できます。セクションヘッダーの**Add new page**ボタンをクリックして、新しいページをすばやく作成することもできます。
- **Tables:** データベーステーブルの表示と管理を行います。
- **Object Manager:** グリッド、テーブル、スケジュールの管理を行います。
- **Scheduled SQL:** 定期的に自動実行されるSQLクエリを管理します。スケジュールはテーブルではなくプロジェクトに属します。セクションヘッダーの**Add new scheduled SQL**ボタンをクリックして、新しいスケジュールルールをすばやく作成することもできます。
- **Settings:** プロジェクトの設定にアクセスします。
- **Docs:** ドキュメントへのリンクです。
- **GitHub:** ソースコードへのリンクです。

## テキストの編集と装飾

Outlinerでは、Scrapbox風の記法を使用してテキストに装飾を適用できます。

### テキストの装飾

- 太字: 二重の角括弧で囲む `[[太字]]`
- 斜体: スラッシュ付きの角括弧で囲む `[/斜体]`
- 打ち消し線: ハイフン付きの角括弧で囲む `[-打ち消し線]`
- 下線: `<u>` と `</u>` タグで囲む `<u>下線</u>`
- コード: インラインコードをバッククォートで囲む \`code\`
- URL: 入力されたURLは自動的にクリック可能なリンクになります
- チェックボックス: インラインチェックボックス `[ ]` (未完了) および `[x]` (完了)
- 書式は組み合わせることができます（太字の中に斜体を含めるなど）。

## アイテムの操作

アウトライナーとしての強力なアイテム操作機能を提供します。

### 新しいアイテムの追加

`Enter`キーを押すと、現在のアイテムの下に新しいアイテムが追加されます。ドキュメントツールバーの **アイテム追加** (Add Item) ボタンをクリックすることでも追加できます。

### アイテムの字下げ（インデント）

- インデントを上げる: `Tab`キー（上のアイテムの子アイテムになります）
- インデントを下げる: `Shift + Tab`キー

### アイテムの移動

ドラッグ＆ドロップでアイテムの順序を簡単に入れ替えることができます。また、`Alt + ↑` および `Alt + ↓` を使用して、現在のアイテム（およびその子アイテム）を兄弟アイテムの中で上下に移動させることもできます。

## 元に戻すとやり直し

元に戻す（Undo）とやり直す（Redo）はプロジェクト全体の単一の履歴に基づいています。

### ショートカット

- `Ctrl+Z` で直前の変更を元に戻します。
- `Ctrl+Shift+Z` または `Ctrl+Y` でやり直します。

### ツールバーボタン

ウィンドウ上部のツールバーにある **Undo（元に戻す）** と **Redo（やり直す）** ボタンは、ショートカットと全く同じ動作をします。スマートフォンでは画面下部のアクションツールバーに表示されます — ソフトウェアキーボードにはCtrlキーがないため、そこから履歴にアクセスします。

元に戻す（またはやり直す）操作がない間は各ボタンはグレーアウトされ、変更を行うとすぐに利用可能になります。編集中にボタンを押してもカーソル位置は保持され、ソフトウェアキーボードも開いたままになるため、そのまま入力を続けることができます。

アウトラインとすべてのデータベーステーブルは内部的にそれぞれの変更履歴を保持していますが、どちらにいるかを意識する必要はありません。これらは順番通りに一つのスタックとして機能します。例えば、行を編集した後にテーブルに行を追加し、2回「元に戻す」を実行すると、まずテーブルの行が削除され、次に編集内容が元に戻ります。他のユーザーが同時に行っている変更が元に戻されることはありません。

## リンク機能

Outliner内の他のページや、外部のウェブサイトへのリンクを作成できます。

### 内部リンク

`[` を1回入力し、ページ名を入力することで、他のページへの内部リンクを作成できます（例: `[ページ名]`）。

- まだ存在しないページへのリンクは見た目が異なり、そのページを編集した時点で初めて作成されます。
- `[/project/page]` の構文を使用して、別のプロジェクトのページにリンクすることもできます。
- **リンクプレビュー:** 内部リンクにカーソルを合わせると、そのページの内容のプレビューが表示されます。
- **バックリンク:** 現在のページにリンクしているページは、下部のバックリンクパネルに一覧表示されます。
- **グラフビュー:** プロジェクト内のページがどのようにつながっているかを視覚化します。各ページのヘッダーにある **Graph View** ボタンをクリックしてアクセスできます。

### 外部リンク

URLをそのまま貼り付けると、自動的に外部リンクとして認識されます。

## 検索とコマンド

Outliner内でコンテンツを簡単に検索し、アクションを実行できます。

- **検索:** 画面上部にある「Search pages」入力フィールドを使用して、プロジェクト全体をすばやく検索できます。最近の検索履歴は素早くアクセスできるように記憶されます。
- **検索と置換:** ページヘッダーの **Search** ボタンをクリックすると、検索と置換パネルが開きます。置換機能はアイテムのテキストのみを書き換えます。「Include page titles」にチェックを入れない限り、ページタイトルは変更されません。このオプションをオンにしてページ名を変更すると、まず確認が行われ、開いているページは新しい名前に追従します。
- **コマンドパレット:** アイテム内で `/` を入力すると、インラインのコマンドパレットが開きます。DatabaseやAliasの挿入などのオプションが利用できます。
- **パンくずリスト:** 各ページの上部にあるパンくずリストを使用して、プロジェクトやホームにジャンプして戻ることができます。

## 選択とクリップボード

複数のアイテムやテキストの範囲を効率的に選択・コピーできます。

### テキストの選択

- `Shift + 矢印キー`: 文字単位・行単位での選択。選択範囲は複数のアイテムにまたがることができます。
- `Ctrl+L` でカーソルのある行全体を選択します。
- `Shift+Alt+Right` で選択範囲を行の末尾まで拡大し、`Shift+Alt+Left` で縮小します。
- `Alt+Shift+矢印キー`（または `Alt+Shift+マウスドラッグ`）でアイテムをまたぐ矩形選択を作成します。

### コピーと貼り付け (Copy and Paste)

- **プロジェクトをまたいだコピー:** アイテムのコピーと貼り付けは、異なるプロジェクト間でもスムーズに機能し、ネストされたすべてのコンテンツが転送されます。
- **形式を選択して貼り付け (Paste Special):** `Ctrl/Cmd+Shift+V` を押して「形式を選択して貼り付け」を開きます：別のライブビュー、データあり/なしの独立したコピー、またはプレーンテキストから選択します。利用できない選択肢も表示されたままであり、その理由が説明されます。

### タッチ操作での選択 (スマートフォン・タブレット)

- 文字をタップするとキャレットが配置され、キーボードが開きます。
- 長押しすると、指の下にある単語が選択されます。
- 指を離さずにドラッグすると、下のアイテムにまたがって選択範囲を広げることができます。
- 通常のスワイプでは、通常通りアウトラインがスクロールします。

### 矩形選択（ボックス選択）

複数のアイテムにまたがる特定の範囲を四角く選択できます。

- マウス操作: `Alt + Shift + ドラッグ`
- キーボード操作: `Alt + Shift + 矢印キー`

### 選択範囲に対する操作

選択範囲がアクティブな場合、以下の操作が可能です：

- 複数のアイテムにまたがる場合でも、コピーと貼り付けができます。
- 選択範囲全体を一度に削除できます。
- 選択したテキストをドラッグ＆ドロップで移動できます。
- 選択した範囲に太字や斜体などの書式を適用できます。

コピーした選択範囲にコンポーネントブロックが含まれる場合：

- **Grid（グリッド）** を同じプロジェクト内に貼り付けると、同じテーブルと Data Storage の別のライブビューが作成されます。
- 別のプロジェクトに貼り付けると、新しい識別子、コピーされたスキーマ、UI 設定、および貼り付け時の行のスナップショットを持つ独立した Grid が作成されます。SQL 名が競合する場合は書き換えられます。
- **Calendar** ブロックはプロジェクトをまたいで貼り付ける際、ポータブルな設定を保持します。
- `Ctrl+Shift+V` (または `Cmd+Shift+V`) を押して「形式を選択して貼り付け」を使用します：別のライブビュー、データあり/なしの独立したコピー、またはプレーンバリューから選択できます。選択できないオプションは表示されたままで、その理由が説明されます。
- 切り取りと貼り付けは、データを削除せずにビューを移動させます。
- プロジェクト間の貼り付けで、クエリの依存関係のコピー、SQLリレーションの名前変更、アウトラインアイテムの再バインド、スケジュールルールの省略、または切り取られたテーブルのソースへの残存など、隠れた結果が生じた場合、何が起こったかを正確に示す一時的なサマリーが表示されます。
- Outliner の外では、コピーしたものは見たままに貼り付けられます。スプレッドシートには Grid の行がセルとして、ドキュメントにはテーブルとして貼り付けられ、Chart ビューが開いている場合は数字と一緒に画像も貼り付けられます。

## 高度な機能

Outlinerにはエイリアスやスケジュールルールなどの高度な機能が含まれています。

- **テーブル間の集計 (Aggregation across tables):** プロジェクト内の各テーブルは、そのスキーマで宣言された名前で参照できます。別のテーブルを結合するクエリを持つテーブルを作成できます（例: 目標値とSalesテーブルの比較など）。
- **エイリアス:** あるアイテムが別のアイテムのミラーとなり、元のアイテムと同期させることができます。
- **スケジュールルール:** ページの予約公開や、テーブルでのSQLの定期実行（日次や週次でのタスク追加など）を設定できます。スケジュールはテーブルではなくプロジェクトに属します。サイドバーの **Scheduled SQL** またはプロジェクトのスケジュールページを開いて、作成と管理を行います。Schedule パネルおよび「Edit Schedules」ページの Edit / Delete の左にある「Run now」を押すと、次回の実行を待たずにルールの SQL をその場で試せます。定期実行のスケジュールは変わらず、ルールが無効でも実行できます。
- **コメントと投票:** アイテムについて議論したり、投票したりできます。アイテムにはコメント数を示すバッジが表示されます。投票数ボタンをクリックするか、右クリックして「アイテムに投票」を選択して、同意を示すことができます。
- **公開と共有:** ページやプロジェクトは編集者以外にも共有できます。共有: 編集権限を与えずにプロジェクトを共有するための読み取り専用トークンを生成します。トークンはプロジェクト設定（サイドバーの「Settings」からアクセス）で生成されます。予約公開: ページを後で自動的に公開するように予約します。スナップショット: スナップショット差分ビューアは、ページが以前のバージョンと比較してどのように変更されたかを表示します。ドキュメントツールバーの **履歴 / 差分** (History / Diff) ボタンからアクセスできます。
- **共同編集:** 他のユーザーとリアルタイムで編集できます。他のユーザーが入力している間、そのユーザーのカーソルと選択範囲を見ることができます。
- **リモート MCP アクセス (Remote MCP Access):** Outliner のオンプレミスサーバーは、互換性のある AI クライアント向けに読み取り専用の MCP エンドポイントを公開しています。通常の Outliner プロジェクトまたはページの URL をクライアントに貼り付けると、`resolve_url` が人間が読めるタイトルを安定した ID に変換します。テキスト、グリッド、カレンダー、レイアウトは、ダミーのテキストに平坦化されるのではなく、個別のセマンティックノードの種類として保持されます。プロジェクトの読み取りにはサインインしているユーザーの既存のプロジェクトアクセス権が使用され、大規模な構造の読み取りには制限が設けられます。初期の MCP ツールは Outliner データの作成、更新、移動、削除を一切行いません。

## レイアウト

レイアウトを使用すると、ビジュアルブロックを横に並べて配置できます。レイアウト自体は通常のアウトラインアイテムであり、ツリー構造を通じて子要素を保持します。削除、コピー、または移動すると、他のアイテムと全く同じように動作します。

- **グリッドシステム:** レイアウトは固定の12カラムグリッドです。内部の各ブロックは、いくつのカラムを使用するか（1から12）のみを保存します。行と列は、そのスパンとアウトライン内のブロックの位置から決定されます。
- **ツリー順序付け:** 座標、行番号、ピクセル幅など、配置に関する他の情報は保存されません。そのため、ブロックの並べ替えは通常のツリーの並べ替えであり、配置はそれに追従します。
- **許可されるコンテンツ:** レイアウトの直下に配置できるのはビジュアルブロック（データベースとカレンダー）のみです。通常のテキストやネストされたレイアウトは拒否されるため、テキスト編集は1次元のままです。
- **サイズ変更:** ブロックの右端にあるハンドルをドラッグして1カラムずつスパンを変更するか、− / + ボタンを使用します。同じコントロールをキーボードの矢印キーでも操作できます。
- **スタッキング:** 横に並べて読むにはレイアウトが狭すぎる場合、ブロックはアウトラインの順序で1行に1つずつスタック（縦積み）されます。保存されているスパンはそのまま維持され、幅が戻ると元の状態に戻ります。
- **レイアウトの削除:** レイアウトを右クリックして「Remove layout (keep blocks)」（レイアウトを削除してブロックを保持）を選択すると、ブロックはレイアウトの位置に移動し、コンテナのみが削除されます。これはサブツリー全体を削除する「Delete item」（アイテムを削除）とは異なります。
- **作成方法:** 空のアイテムで `/Layout` と入力してレイアウトを作成し、データベースまたはカレンダーブロックをその上にドラッグします。空のレイアウトは、次のブロックの準備ができた状態でそこにとどまります。

## データベーステーブル

プロジェクト内で構造化されたデータを管理するためのデータベーステーブルを作成できます。空のテーブルから始めることも、Tasks（タスク）やHabits（習慣）などのプリセットを使用することもできます。

- **タスクマネージャー (Task manager):** 期限、優先度、繰り返し間隔を持つタスクを追加できます。ステータスと優先度のオプションは、スキーマの CHECK 制約から取得されます。
- **習慣トラッカー (Habit tracker):** 1つのテーブルで習慣の定義と日々の達成ログを保持します。今日のログ行を追加して継続記録（ストリーク）を伸ばします。

### データベーステーブルの作成

上部のナビゲーションバーの左側にある **Add Database**（データベース追加）ボタンをクリックします。

現在のページの一番下に新しいデータベースブロックが挿入されます。このブロック内で以下の操作が可能です：

- **New Table:** テーブル名を入力し、プリセット（Table, Tasks, Habits など）を選択し、**Create** をクリックします。クエリで参照されるSQL名は自動的に生成され、入力フィールドの下に表示されます。
- **New Grid over Existing Table:** このタブに切り替え、既存のテーブルを選択して **Select** をクリックすることで、そのテーブルのデータにリンクされた新しいビュー（グリッド）を作成します。
- **Existing Grid:** このタブに切り替え、以前に作成したグリッドを選択して **Select** をクリックすることで、既存のグリッドを埋め込みます。

さらに、上部のナビゲーションバーの右側にある **Databases**（データベース）ボタンをクリックすると右側のドロワーが開き、既存のデータベースを表示および管理できます。このサイドバーには、すべてのテーブル (TABLES) がリスト表示されます (例: Sales, Tasks, Routine Templates, Routine Occurrences など)。

### データの管理

テーブルが作成されると、レコードの追加、編集、削除ができるグリッドビューが表示されます。

- 上部のボタンを使用して、テーブルの異なるビューを切り替えることができます。
  - **Grid（グリッド）:** データ行を追加および編集するためのデフォルトのビュー。
  - **Chart（チャート）:** データの視覚的な表現。
  - **Schema（スキーマ）:** テーブルのSQLスキーマを定義・編集できます。
  - **UI:** 列の表示方法（テキスト、チェックボックス、日付、セレクトドロップダウンなど）をカスタマイズするエディタ。
  - **Schedule（スケジュール）:** テーブルに対する定期的なスケジュールルール（日次/週次でのタスク追加など）を作成・管理するためのビュー。
- テーブルのツールバーには、利便性のために **Undo（元に戻す）** と **Redo（やり直す）** ボタンも用意されています。これらはプロジェクト全体の単一の変更履歴とシームレスに連動します。

### 共同編集

データベースは他のアウトラインデータと同じ仕組みで保存されるため、データの変更やスキーマの更新はプロジェクトに参加している全員にリアルタイムで同期されます。

## カレンダー

カレンダーとは、クエリと結果の列に対する役割の割り当て（どの列がタイトル、開始日、終日フラグ、期間、グループ化の軸になるか）を組み合わせたものです。カレンダー自体はデータを持ちません。

- **クエリと役割:** 役割の候補となるのは、クエリが実際に返す列です（結果の順序であり、固定されたスキーマではありません）。クエリを変更しても、新しい結果から一時的に欠落している列の役割の割り当てが破棄されることはありません。
- **書き込み可能条件:** カレンダーに書き込みを行うには、クエリが `source_kind` と `source_id` の両方を SELECT する必要があります。それ以外の場合、カレンダーは読み取り専用になり、その旨が表示されます。
- **元に戻すとやり直し (Undo and Redo):** 役割の再割り当て、クエリの編集、またはグループ軸の変更はすべて、他のすべての操作と同じ共有履歴上で元に戻すことができます（「元に戻すとやり直し」を参照）。
- **ビューの種類:** 日、アワーマップ (Hour Map)、複数日、週、月、ガントチャートのビューを切り替えることができます。アワーマップビューは、垂直の列ではなく、時間×分のマトリックスとして時間を配置します。ガントチャートビューではエントリごとに1行表示され、アウトライン自体の階層構造に従ってネストされます。日付のある子エントリを持つ親エントリは、自身の日付の代わりに、子エントリの最も早い開始日から最も遅い終了日までをスパンするロールアップバーを表示します。これをドラッグすると、サブツリー全体が1つのUndoエントリとしてシフトします。親エントリ自身の期限（もしあれば）は、ロールアップバーの横にマーカーとして表示されます。軸の粒度（日/週/月/四半期）はビューの設定で変更可能です。
- **ドラッグ＆ドロップ:** エントリをドラッグしてスケジュールを変更したり、下端をドラッグして期間を変更したり、矢印キーで移動させることができます。これら3つはすべて、同じ書き込みパス、同じ書き込み可能チェック、同じ楽観的配置モデルを経由します。ツールバーのセレクトで日 / アワーマップ / 複数日 / 週 / 月 / ガントを切り替えます。ドラッグやサイズ変更の操作中には、マウスポインタの近くにチップが表示され、エントリがどこに配置されるかを正確に示します（例: 移動の場合は "Thu, Aug 3 09:15 – 09:45"、サイズ変更の場合は "09:00 – 10:30 (1h30m)"、Month や Gantt ビューでは日付のみ）。カレンダーのタイムゾーンに合わせてフォーマットされ、ドロップと同じようにスナップされるため、ラベルが書き込まれる内容と異なるものを約束することはありません。
- **スイムレーン:** "tags"（タグ）でグループ化すると、週/日ビューがタグごとのスイムレーンに分割され、月ビューではエントリが色分けされます。エントリの小さなハンドルを別のレーンにドラッグするとタグセットが置き換わり、`Ctrl`（macOSでは `Cmd`）を押しながらドロップすると、置き換えるのではなくレーンのタグが追加されます。
- **安全な操作:** 「New entry（新規エントリ）」では常にどのページの下に作成するかを尋ねられます（暗黙のインボックスはありません）。以前に使用した宛先が最初に提案されます。エントリを削除する場合は常に、エントリ自体を削除するか、日付のみをクリアするかを尋ねるプロンプトが表示されるため、キー操作で誤って書き込みが破棄されることはありません。
