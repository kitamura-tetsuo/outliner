Public Demo Project

This is a public, collaborative demo project. Each page demonstrates a group of features. Content resets every 24 hours, or immediately with the reset button.

Pages

  • Layout

    A Layout arranges visual blocks side by side. It is a normal outline item that owns its children through the tree — deleting, copying or moving it behaves exactly like any other item.

    How it works:

    The Layout is a fixed 12-column grid. Each block inside it stores only how many columns it spans (1 to 12); rows and columns follow from that span plus the block's position in the outline.

    2026-08-23
  • Calendars

    A calendar is a query plus a role assignment over its result columns — which column is the title, the start, the all-day flag, the duration, and which columns are grouping axes. It has no data of its own.

    How it works:

    Candidates are the columns the query actually returns, in result order — never a fixed schema. Changing the query never discards an existing role assignment for a column that is temporarily missing from the new result.

    2026-08-23
  • Recurring Tasks

    Daily and weekly tasks, generated by schedule rules: the SQL of a rule runs again at every occurrence of its recurrence and appends the task of that day or week.

    How it works:

    Two tables: the templates below define what repeats, the occurrences table collects the dated tasks generated from them.

  • Advanced Features

    A quick tour of the more advanced capabilities. The items below are live components, not just descriptions.

    Database tables: this item embeds a live table (Yjs data, SQL queries via PGlite). Toggle the Chart view to render the query result as a bar chart.

    Clipboard: within one project, copying and pasting a selection that crosses a Grid creates another live view of the same table and Data Storage. Across projects, paste instead creates an independent Grid with a fresh identity, copied schema, UI settings, and a paste-time snapshot of its rows; conflicting SQL names are rewritten, and Calendar blocks retain their portable settings. Press Ctrl/Cmd+Shift+V for Paste Special: choose another live view, an independent copy with or without data, or plain values. Unavailable choices stay visible and explain why. This public demo has only one project, so try the same-project choices here. Cut and paste moves the view without deleting its data. When a cross-project paste has a hidden consequence—such as copying query dependencies, renaming SQL relations, rebinding outline_items, omitting schedule rules, or leaving a cut table in the source—a transient summary names exactly what happened. Outside Outliner the same copy pastes as what you see: a spreadsheet receives the Grid's rows as cells, a document receives them as a table, and with the Chart view open the picture travels with the numbers.

  • Selection and Clipboard

    Select text with the mouse or with Shift+Arrow keys.

    Selections can span multiple items: keep extending past the end of an item.

    Drag in either direction: selecting bottom-to-top highlights exactly the same text as top-to-bottom.

  • Schedule Rules

    Pages can be scheduled to be published at a later time.

    Tables can run SQL on a recurrence: see [Recurring Tasks] for two live rules that add the tasks of the day and of the week.

    Schedules belong to the project, not to a table: open the Schedules section in the sidebar to create a rule of your own.

  • Remote MCP Access

    Outliner's on-premises server exposes a read-only MCP endpoint for compatible AI clients.

    Paste a normal Outliner project or page URL into the client; resolve_url converts its human-readable titles to stable IDs.

    Text, Grid, Calendar, and Layout remain distinct semantic node kinds instead of being flattened into fake text.
